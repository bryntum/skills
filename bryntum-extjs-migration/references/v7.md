# bryntum-extjs-migration 7.x reference

Applies to **7.x targets only** (see the version check in the core `bryntum` skill). It replaces the 8.0 statements below
in `SKILL.md` and the other references for those apps. Everything not listed here applies to both versions. A 7.x app
that should move to 8.0 is a `bryntum-migrate` job (7.x → 8.x hop), not part of the Ext migration. Raw URL:
https://raw.githubusercontent.com/bryntum/skills/refs/heads/main/bryntum-extjs-migration/references/v7.md

## Tiers and license key (replace "Tier and license")

7.x has no tiers and no `bryntum.licenseKey`: every feature is in the package, and trial vs licensed is a package choice.
Ignore `api-mapping.md` §0. Never add a key to a 7.x app. Record "trial" or "licensed" (registry or local build) in
`MIGRATION_PLAN.md` instead of a tier.

## Install (replaces "Install")

- **Trial** (public npm, no auth, watermarked): `npm install @bryntum/{product}@npm:@bryntum/{product}-trial`. Framework
  wrappers have no `-trial` suffix. Pin the product and its wrapper to the same exact version.
- **Licensed**: the private `npm.bryntum.com` registry (`npm-us.bryntum.com` for the US one) with a token, or a local build.
  `@bryntum/{product}` on **public** npm is a placeholder. If licensed access fails, do the work that doesn't need the
  package and mark verification as blocked. Don't switch to the trial without asking.
- A global `~/.npmrc` that maps `@bryntum:registry` to `npm.bryntum.com` makes the trial resolve against the private
  registry. Add a project `.npmrc` with `@bryntum:registry=https://registry.npmjs.org/` to use public npm for that project.
- When switching between trial and licensed packages, move `package-lock.json` and `node_modules/` aside first. The
  lockfile silently keeps the old package source.

## Packages, imports and CSS

| 8.0 (default in this skill) | 7.x |
|---|---|
| `@bryntum/<product>-<tier>`, wrappers `@bryntum/<product>-<framework>-<tier>` | `@bryntum/<product>`, `-react`, `-angular`, `-vue-3` |
| Scheduler Pro = `@bryntum/scheduler-enterprise`, class `Scheduler`, `BryntumScheduler` | `@bryntum/schedulerpro`, `SchedulerPro`, `BryntumSchedulerPro` |
| Each package exports its own classes: `Store`, `Popup`, `Toolbar`, `LocaleHelper` from `core-<tier>` | The product package re-exports everything it is built on: `import { Toolbar, Popup, LocaleHelper } from '@bryntum/<product>'` |
| Locales `@bryntum/<product>-<tier>/locales/<product>.locale.Es` | `@bryntum/<product>/locales/<product>.locale.Es` |
| Font Awesome from `@bryntum/core-<tier>/fontawesome/css/` | Font Awesome CSS from the product package |
| Chart: `@bryntum/chart-enterprise` (Enterprise only) | `@bryntum/chart-thin` |
| `build.cssTarget` needed in Vite | not needed |
| Vite: leave `optimizeDeps` alone | Vite `optimizeDeps` pre-fill per the 7.x quick start |

CSS (7.x): `@bryntum/<product>/<product>.css` + one theme file + the Font Awesome sheets, as plain `@import`s. Core skill
`references/v7.md` has the exact lines.

## Scheduler Pro

Scheduler and Scheduler Pro are separate products with separate packages. Read "Scheduler Enterprise" in the references
as Scheduler Pro, and `products/schedulerpro.md` as the Scheduler Pro page. Its editor feature is `taskEdit`, Scheduler's
`eventEdit`. Scheduler (not Pro) uses `crudManager`; Scheduler Pro and Gantt use `project`.

## Verified version

The references were first verified against Bryntum 7.3.7, so every "7.3.7 bug" note applies as written to 7.x apps
(`items : { someBuiltIn : true }` blanking built-ins, a function `field` in `groupers`, a typed `id` in a grouped
store, the editor title overwritten before `beforeEventEditShow`, the Material3 `datetimefield` label overlap). On 7.x
below 7.3.7, confirm each name against the installed `*.d.ts` before using it.

## Bryntum-in-Ext screens (type B) on 7.x

If the screen only needs its Ext shell removed and the app stays on 7.x, follow the Ext skill with this file. If the
Bryntum code should also go to 8.0, do the shell removal first, then run `bryntum-migrate`, so each step can be verified.
