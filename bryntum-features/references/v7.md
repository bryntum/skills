# bryntum-features 7.x reference

Applies to **7.x apps only** (see Version check in the `bryntum` skill). It adds the 7.x rules below to the `bryntum-features` skill and its reference files for those apps. Raw URL: https://raw.githubusercontent.com/bryntum/skills/refs/heads/main/bryntum-features/references/v7.md

## Tiers

7.x has no tiers. Ignore the Tier column of the Index and every tier mark in the reference files: a feature is available if the product has it.

- Read "Scheduler Enterprise" as Scheduler Pro (`@bryntum/schedulerpro`, class `SchedulerPro`) and "Scheduler Community/Business" as Scheduler. Of the Scheduler features marked Enterprise, `resourceNonWorkingTime`, `timeSpanHighlight`, `nestedEvents`, `eventSegments`, `taskEdit` and `versions` are Scheduler Pro's; the others are in `@bryntum/scheduler` or `@bryntum/grid`.
- There is no Gantt Community: Gantt always runs the full engine and edits with `taskEdit`. `basicTaskEdit` does not exist.
- Calendar has no `multiweek` mode; the other modes listed are available.
- A product package contains the products it is built on, so a Gantt needs no extra import for Scheduler or Grid features or widgets.

## How features behave

Configure features at construction. A feature added to `features` after the component is built never runs its paint-time init. To switch one on later, include it in the config and flip `widget.features.x.disabled = false`.

## Things that do not exist

- `Grid#refresh()` — Grid has `refreshRows()` and `refreshColumn()`. Calendar, TaskBoard, Scheduler and Gantt do have `refresh()`.
- An unknown feature key (`eventTooltip` in Gantt) is silently ignored rather than throwing.
